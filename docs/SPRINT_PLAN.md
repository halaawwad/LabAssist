# خطة السبرنتات وتوزيع الشغل — LabAssist

> هاي الخطة اللي اتفقنا نمشي عليها بعد تجهيز الفرونت والداتابيس. الشغل بيشمل **الويب والتطبيق والأدوار كلها**.
> المعمارية: **Client–Server مع Modular Monolith Backend** باستخدام NestJS وPostgreSQL وPrisma.

## 1. مسار كل سبرنت

كل سبرنت بيمشي بنفس الترتيب:

1. مراجعة الداتا والعلاقات.
2. الباك: DTO وController وService وRepository والصلاحيات.
3. الـAPI.
4. ربط الويب والتطبيق.
5. الاختبارات وإصلاح المشاكل.

## 2. السبرنتات

## 3. التوزيع على الجولات

عدد السبرنتات لحاله ما ببيّن توازن الشغل، فالتوزيع ماشي بالجولات وبحجم الشغل، مش بعدد السبرنتات.

| الجولة | نور | حلا | التنسيق المطلوب |
|---|---|---|---|
| 1 | إغلاق 1 — الحسابات والصلاحيات (ومعها حساب رئيس القسم ودخوله وصلاحياته) | 6 — الكاتالوج والمحلات والعروض | تثبيت هوية المستخدم وعقود الصلاحيات؛ جزء العروض المرتبط بالمشاريع ينتظر 2A |
| 2 | 2A — المشاريع والفرق والمهام والمشاكل، ومعها ربط واجهة رئيس القسم الموجودة للحسابات والتفعيل والمجموعات والمشاريع | إكمال الكاتالوج وتجربة تقنية صغيرة للـAI | تثبيت عقود المشروع والفريق والقطع، وتجهيز أساس الإشعارات |
| 3 | 3A — التقارير الأسبوعية | 2B — القطع والميزانية، ثم 4 — الورشة | بعد دمج أساس 2A؛ توحيد هوية الفريق وحفظ تاريخ التغييرات |
| 4 | 3B — التقرير النهائي والعرض | 5 — الرسائل والاجتماعات والإشعارات (ومعها رسائل وإشعارات رئيس القسم) | الاتفاق على المرفقات والتخزين والإشعارات |
| 5 | 7 — مختبر الدارات | 8 — Learning Hub والـAI | ربط بيانات القطع، ومراجعة التقارير بالـAI، وتجربة التكامل |
| النهاية | فحص وإصلاح مشترك | فحص وإصلاح مشترك | الويب والتطبيق والأدوار الأربعة |

- **كل جولة بتنتهي بفحص تكامل** بين شغل نور وشغل حلا، على الويب والتطبيق. التكامل والفحص مش مؤجّلين لآخر المشروع.
- **بنراجع الحمل بعد الجولة الأولى**، وبنعدّل التوزيع لو ظهر جزء أصعب من المتوقع بدل الالتزام بتوزيع ثابت.
- إذا خلصت وحدة قبل الثانية، بتساعد بمهمة محددة ومتفق عليها.

## 4. ملكية الميزة

كل وحدة مسؤولة عن ميزتها **كاملة**:

- الداتا (Prisma schema وتغييرات الترحيل الخاصة بالميزة).
- الباك (DTO وController وService وRepository والصلاحيات).
- الـAPI وتوثيقه.
- ربط الويب والموبايل.
- الاختبارات.

## 5. تجنّب التعارض

ما في تقسيمة بتضمن صفر conflicts؛ بنقلّلهم بملكية واضحة وتنسيق الملفات المشتركة.

### Prisma والترحيلات

ملفات schema منفصلة لحالها ما بتمنع التعارض، فبنمشي هيك:

- **نور بتنسّق ترحيلات الداتابيس مبدئيًا**: كل وحدة بتجهّز تغييرات ميزتها، ونور بترتّب دمجها وتشغيلها.
- تغيير المسؤولة عن الترحيلات بيصير **بس عند بداية جولة وباتفاق واضح**.
- كل migration بتنعمل **فوق آخر نسخة مدموجة على main**.
- كل migration بتنجرّب **من قاعدة فارغة ومن النسخة السابقة**.

### الملفات المشتركة

- مش كل الملفات المشتركة على نور.
- لكل تعديل مشترك **مسؤولة واحدة مؤقتًا**، والثانية بتراجعه.
- هذا خصوصًا للجلسات، التنقّل، عميل الـAPI والمكوّنات المشتركة.

### Git

- برانش لكل ميزة وPR واضح.
- تحديث البرانش من main قبل الدمج.
- ممنوع إعادة كتابة تاريخ برانش بتشتغلوا عليه سوا.

## 6. رئيس القسم

| الجزء | المسؤولة | الموعد |
|---|---|---|
| الحساب والدخول والصلاحيات | نور | سبرنت 1 (الجولة 1)، حتى لو تأجّل ربط الواجهة |
| ربط الواجهة الموجودة للحسابات والتفعيل | نور | الجولة 2 |
| ربط المجموعات والمشاريع بواجهة رئيس القسم | نور | الجولة 2 ضمن 2A |

- **تأجيل واجهة رئيس القسم مؤقت**، مش إلغاء، وإلها موعد واضح بالجولة الثانية.
- ما بنعيد تصميم الواجهة؛ بنربط الواجهة الموجودة.

## 7. الاختبارات والأدوات

- **الاختبارات بتبدأ من أول سبرنت**: Unit وIntegration وAPI والصلاحيات، ومعها E2E للويب والتطبيق حسب الميزة.
- العمليات الحساسة إلها **Concurrency Tests** من سبرنتها.
- **TDD للقواعد الجديدة**: اختبار يفشل، تنفيذ، ثم تحسين الكود.

| الأداة | دورها |
|---|---|
| Swagger | توثيق الـAPI |
| Postman | تجربة الـAPI |
| Jest وLCOV | الاختبارات والتغطية |
| SonarQube | التحليل |
| GitHub Actions | التشغيل الآلي |
| k6 | اختبارات الحمل |

JaCoCo خاص بـJava، فمش أداة التغطية المناسبة لباك TypeScript.

### المرحلة النهائية

Full E2E + Regression + Load/Stress + إعادة فحص التزامن + Acceptance Testing مع المستخدمين، ثم الإصلاحات والتوثيق.

## 8. وضع السبرنت الأول (حسب آخر تحديث من نور)

اللي خلص:

- ترتيب الباك إلى Modules وControllers وServices وRepositories وDTOs.
- API الدخول والتفعيل والاستعادة وتجديد الجلسة والخروج والتحقق من الحساب والصلاحيات.
- كلمات المرور محفوظة بـ**Argon2id hash**، وروابط التفعيل والاستعادة بتنجرّب ببريد محلي بدون إرسال لأشخاص حقيقيين.
- ربط مسار الدخول بالتطبيق للطالب والمشرف ومسؤول الورشة، وفحص السيناريوهات عبر معاينة المتصفح.
- نجح 22 اختبار للباك و62 اختبار ضمن حزمة الموبايل قبل آخر تعديل لمشاركة منطق الجلسات، ونجح بناء iOS.

اللي باقي (السبرنت الأول **لسه مش مسكّر**):

- إكمال التحقق من ربط الويب للأدوار الثلاثة ومن آخر التعديلات.
- آخر تعديلات التطبيق.
- تشغيل اختبار الحمل الجاهز (30 طالبًا و5 مشرفين ومسؤول ورشة).
- تجربة على iPhone فعلي.
- تجهيز Sonar والتغطية.
- حساب رئيس القسم ودخوله وصلاحياته.

> ملاحظة: تعديلات نور الحالية محلية ولسه ما انرفعت على GitHub، فشكل الكود على main ممكن ما يعكس آخر وضع للسبرنت الأول.

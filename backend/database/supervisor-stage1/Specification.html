Additive extension of the student foundation. One shared database; no duplicated student accounts, projects or supervisor links. No passwords or invitation secrets in the demonstration seed.

Scope

Profile, specialization, optional office hours, profile image metadata, Arabic/English preferences, notification settings and private notification read timestamps.

Supervisor account ? project_supervisors ? Project ? project_students ? Students

A supervisor is linked once per project. A project can have multiple supervisors. The student's account supervisor remains a separate existing relationship. Project access follows the project-supervisor association.

Preserved relationships

  • Supervisor identifiers reuse the student-stage1 seed, without changing account status or passwords.
  • Students keep eight-digit university numbers and their original account supervisor.
  • UNIQUE / primary keys prevent duplicate supervisor-project links.
  • Seed replay does not reset edited profiles or preferences.

Constraints

Only supervisor accounts can own these rows. Photos must be ready images owned by that supervisor. UI locale accepts ar/en. Settings default to notifications enabled and email summaries disabled.

Boundaries

This does not connect the mock UI to a backend. API authorization, real authentication, report/review workflows, messages, delivery and multi-connection concurrency tests remain separate implementation stages. The relationship view is not an authorization boundary. Passwords are stored as Argon2id hashes after real account provisioning; no plaintext passwords are seeded.

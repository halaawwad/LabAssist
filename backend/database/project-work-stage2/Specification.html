Derived views

project_member_work_summary: total, done, in progress, remaining, overdue and personal progress. project_team_work_summary: mean member progress, open tasks and open issues. No static completion percentages are stored.

Shared identities

References existing accounts, project_students and projects. Students are equal teammates. No Leader/Member role or project code is introduced.

Permissions & lifecycle

  • Any current teammate can create a TODO task for any current teammate.
  • Only the assigned student can update that task, confirm completion or request help.
  • Completion records a timestamp and clears help; correcting completion clears the timestamp.
  • Any current teammate can create/update/resolve project issues.
  • A resolved issue requires a resolution note and records who resolved it and when.
  • Supervisors do not mutate student work in this stage; backend read access follows project_supervisors.
  • Project/task identity and history cannot be rewritten.
  • Row-locking status functions reject stale expected revisions. This is not evidence of a tested multi-connection race.

Backend boundary

The authenticated backend must derive actor identity from the session, scope reads and apply expected revisions to edit endpoints. No client database credentials, RLS claim or live API is provided. Task reassignment/deletion and broader lifecycle permissions are not implemented in this stage.
